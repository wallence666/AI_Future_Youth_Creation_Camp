# 澳行無阻 · 前後端分離功能規格書（Spec）

> 版本：v1.2（第三輪修訂：店舖開放打卡）　狀態：**已確認生效**（用戶於第三輪回覆確認）　約束：開發以此文檔為唯一依據；未列入本文檔的功能一律不實現。

## 0. 目標與原則

1. 引入三類角色：**遊客**、**商家**、**管理員**，均可在應用內註冊/登入。
2. 遊客貢獻內容（人流回報、打卡、評論、照片）→ 獲得**積分**；積分可兌換商家發佈的**代金券**。
3. 遊客人流回報進入 CrowdIndex 模型，成為擁擠度估算的**實時權重因子**。
4. 商家申請入駐 → 管理員審核 → 店舖上架地圖；商家可維護照片、菜單、營業時間、限時活動。
5. 架構調整：**前後端分離**（REST API）、**代碼模塊化**、**PWA 化**（可安裝到手機主屏，脫離微信小程序獨立運行）。

已確認的技術決策（第一輪問答）：

| 項 | 決策 |
|---|---|
| 後端 | Node.js + Express + SQLite（better-sqlite3） |
| 獨立 APP 形態 | PWA（manifest + Service Worker，可添加至主屏） |
| 認證 | 賬號 + 密碼（bcrypt 哈希 + JWT） |
| 管理員審核 | 簡易管理後台網頁 |

## 1. 角色與權限矩陣

| 能力 | 未登入 | 遊客 | 商家 | 管理員 |
|---|---|---|---|---|
| 瀏覽地圖/熱力/美食/詳情 | ✓ | ✓ | ✓ | ✓ |
| 人流回報 | ✗ | ✓ | ✓ | ✓ |
| 打卡（景點＋店舖） | ✗ | ✓ | ✗ | ✗ |
| 評論 / 上傳照片（景點＋店舖） | ✗ | ✓ | ✗ | ✗ |
| 積分獲取與兌換代金券 | ✗ | ✓ | ✗ | ✗ |
| 提交店舖資料 / 管理自家店舖 | ✗ | ✗ | ✓ | ✗ |
| 發佈限時活動（代金券） | ✗ | ✗ | ✓（已通過審核） | ✗ |

- 商家註冊後為 `pending` 狀態：可登入商家中心填寫店舖資料，但**審核通過前店舖不上地圖**。

## 2. 功能需求

### F1 賬號系統
- 註冊：用戶名（3–20 位英數）+ 密碼（≥6 位）+ 角色（遊客/商家）。
- 登入：簽發 JWT（7 天有效），前端存 localStorage，API 請求帶 `Authorization: Bearer`。
- 遊客註冊即送 **+20 積分**。
- 提供「我的」頁：暱稱、角色、當前積分、積分明細、我的打卡數、我的評論、我的代金券。

### F2 人流互助問卷（遊客 → 模型）
- **觸發方式（雙通道）**：
  1. 自動：App 打開且定位授權時，若用戶進入某景點半徑 **150 m** 內，彈出一次快捷問卷（同景點 30 分鐘內不重複彈）。
  2. 手動：景點詳情卡常駐「我在現場，回報人流」按鈕（未授權定位時也可用，但不享受自動觸發）。
- **問卷內容**：單選三檔 —— 「暢通 / 一般 / 擁擠」。
- **防刷**：同用戶同景點 30 分鐘限 1 次；提交需登入。
- **獎勵**：每次有效回報 **+6 積分**。

### F3 打卡（景點＋店舖，用戶第三輪修訂）
- **景點、官方收錄美食、入駐店舖**的詳情卡均有「打卡」按鈕；需登入 + 定位授權，且距目標 ≤ **500 m**（演示可用瀏覽器模擬定位）。
- 同一目標每日限打卡 1 次，成功 **+10 積分**；詳情卡顯示累計打卡人數。
- 實現：checkins 表以 `target_type[spot|food|shop] + target_id` 多態關聯（與 comments 同構）。

### F4 評論與照片（景點＋店舖，用戶第二輪修訂）
- **景點、官方收錄美食、入駐店舖**的詳情卡均有評論區：文字（≤200 字）+ 可選照片（≤3 張，單張 ≤5 MB，jpg/png/webp）。
- 發表評論 **+5 積分**（同一目標每日最多 3 條計分）；附照片每條再 **+8 積分**（每日最多 2 條計分）。
- 評論按時間倒序分頁（每頁 10 條）；作者可刪除自己的評論；管理員可刪除任何評論（作者 −5 積分）。
- 實現：comments 表以 `target_type[spot|food|shop] + target_id` 多態關聯；入駐店舖 target_id 加 `shop_` 前綴避免與靜態 food id 衝突。

### F5 積分系統
| 行為 | 積分 | 限額 |
|---|---|---|
| 註冊遊客 | +20 | 一次 |
| 人流回報 | +6 | 同景點 30 分鐘 1 次 |
| 打卡（景點/店舖） | +10 | 同一目標每日 1 次 |
| 評論（景點/店舖） | +5 | 同一目標每日 3 條計分 |
| 評論附照片 | +8 | 每日 2 條計分 |
| 評論被管理員刪除 | −5 | — |
| 兌換代金券 | −商家設定值 | 庫存與活動期內 |

- 所有積分變動寫入 `points_log`，「我的」頁可查流水。

### F6 商家中心（獨立頁面 `/app/merchant.html`）
商家登入後可管理**一家**店舖：
- 基本資料：店名、菜系分類（沿用現有 6 類 +「其他」）、人均消費、地址、地圖選點（lat/lng）、營業時間、簡介。
- 照片上傳：門頭/環境/菜品（≤6 張）。
- 菜單：條目式（菜名 + 價格），≤30 條。
- 限時活動（代金券）：標題、說明、所需積分、券面價值（MOP）、起止時間、庫存數量；可隨時下架。
- 提交/修改資料後：首次需管理員審核；之後修改基本資料不重新審核，但**活動與店名修改需重新審核**（防止審核後改名）。
- 核銷：輸入遊客出示的 6 位兌換碼 → 標記已核銷（顯示券信息供商家確認）。

### F7 代金券兌換（遊客）
- 已上架店舖的詳情卡增加「限時活動」區塊：顯示活動、所需積分、剩餘庫存。
- 遊客點「兌換」→ 扣積分、扣庫存 → 生成 **6 位兌換碼**（字母數字），存於「我的代金券」（狀態：未使用/已核銷/已過期）。
- **演示形態（用戶第二輪修訂）**：不涉及真實支付；兌換碼頁同時渲染 **QR 二維碼**（內容即 6 位核銷碼，前端本地生成，不請求外部服務）；商家核銷時手動輸入 6 位碼。
- 過期未核銷的券**不退積分**（文案明示）。

### F8 管理後台（獨立頁面 `/app/admin.html`）
- 管理員賬號預置：`admin / admin123`（首次部署後可在數據庫修改；文檔與演示中明示）。
- 待審核商家列表 → 查看資料 → 通過 / 拒絕（可填拒絕原因）。
- 已上架店舖列表 → 可下架。
- 評論管理：最新評論列表 → 刪除違規評論。
- 簡易數據概覽：註冊用戶數、今日打卡數、今日人流回報數、待審核數。

### F9 PWA 化
- `manifest.webmanifest`：名稱、圖標（192/512）、主題色、standalone 顯示。
- Service Worker：預緩存靜態資源（HTML/CSS/JS/Leaflet/圖標），API 數據採用 network-first + 離線兜底提示。
- 安裝提示：Android Chrome 自動出「添加到主屏幕」；iOS 文案引導用 Safari 分享按鈕。

## 3. 模型改動：CrowdIndex v2（新增 U 因子）

現有模型保持不動（B(s)、Tc、Park 衰減、I、W、H 全部保留），新增**用戶回報因子 U(s,t)**：

```
U(s,t) = Σ( level_i × e^(−λu·Δt_i) ) / Σ( e^(−λu·Δt_i) )
  level ∈ {暢通 0.2, 一般 0.55, 擁擠 0.9}；半衰期 15 分鐘；統計窗口 30 分鐘
最終指數 = (1 − α) × CrowdIndex_v1 + α × U，α = 0.25 × min(有效回報數 / 3, 1)
```

- 有效回報 <3 份時 α 線性遞減至 0，避免單一回報劫持指數。
- U 由後端聚合（`GET /api/crowd/live` 返回各景點 U 與回報數），前端 model.js 負責融合；**模型仍在客戶端運行**，保留離線與演示能力（後端不可用時 U=缺省，全量退回 v1）。

## 6. 數據庫 Schema（SQLite）

```
users(id, username UNIQUE, password_hash, role[visitor|merchant|admin], points, created_at)
checkins(id, user_id, target_type[spot|food|shop], target_id, day, created_at,
         UNIQUE(user_id, target_type, target_id, day))
crowd_reports(id, user_id, spot_id, level[1|2|3], created_at)
comments(id, user_id, target_type[spot|food|shop], target_id, content, photos JSON,
         status[visible|deleted], created_at)
points_log(id, user_id, delta, reason, ref_id, created_at)
shops(id, merchant_id→users, name, cuisine, price, lat, lng, addr, hours, intro,
      photos JSON, menu JSON, status[pending|approved|rejected|takedown], reject_reason, created_at)
promos(id, shop_id, title, desc, points_cost, coupon_value, start_at, end_at, stock, status, created_at)
coupons(id, promo_id, user_id, code UNIQUE, status[unused|redeemed|expired], created_at, redeemed_at)
```

- 景點基礎數據（spots.json）保持靜態文件，`spot_id` 以字串外鍵關聯。
- 現有 45 家官方美食（foods.json）保持靜態「官方收錄」；商家入駐店舖從 API 合併進美食圖層，帶「入駐」角標。

## 7. 安全與限制

- 密碼 bcrypt(10) 哈希；JWT 密鑰走環境變量 `JWT_SECRET`（默認開發值僅本地用）。
- 上傳：multer 限 5 MB/張、白名單 jpg/png/webp、隨機文件名。
- 限頻：回報/打卡/評論接口 per-user 限流（express-rate-limit）。
- 所有寫接口做參數校驗；SQL 全部參數化（better-sqlite3 prepared statements）。
- 管理員接口僅 role=admin；商家接口校驗「只能操作自己的店」。

## 8. 明確不做（Out of Scope）

1. ~~美食店舖的用戶評論~~（已移出不做清單——用戶第二輪修訂：景點與店舖均開放評論）。
2. 不做手機短信驗證、第三方 OAuth、微信登入。
3. 不做真實支付；代金券僅為積分兌換 + 線下出示核銷碼/QR（演示）。
4. 不做即時聊天、關注、私信等社交功能。
5. 不做原生 APP（Flutter/RN）；以 PWA 滿足「獨立手機應用」。
6. 不做多語言（維持繁體中文）。
7. 不修改 CrowdIndex v1 既有因子與權重（僅新增 U 融合層）；既有前端代碼不從零重寫。
8. 商家僅限一家店舖；不做連鎖多店。
9. ~~打卡僅限景點~~（已移出不做清單——用戶第三輪修訂：店舖同樣開放打卡）。

## 10. 實施順序（確認 spec 後按序執行）

1. **P1 後端骨架**：server/ 初始化、DB 建表+seed、auth（註冊/登入/JWT）、靜態託管。
2. **P2 遊客閉環**：前端模塊化重構 + 登入註冊 UI + 人流回報（含 U 融合）+ 打卡 + 評論照片 + 積分。
3. **P3 商家與管理**：商家中心、管理後台、代金券兌換與核銷。
4. **P4 PWA 與收尾**：manifest/sw.js、整體回歸驗證、README 更新。
